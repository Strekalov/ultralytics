# Форк ultralytics: что в нём своё

## База

Ветка `feat/drone-person-configs-8.4.164` построена от тега upstream `v8.4.164` (`9540b3124`). Поверх него лежат только
наши правки, перечисленные ниже; QAT берём из upstream (`quantize=8` в режиме train).

Предыдущая версия форка — ветки `feat/drone-person-configs` (`e058d9557`) и `feat/qat` (`5185143de`) от `b5ccd6d0f`
(8.4.138). Обе удалены 2026-09-29; хэши старых коммитов в таблицах ниже приведены для истории.

### Совместимость

- Чекпойнты, обученные старым QAT из `feat/qat` (ключи `modelopt_state`, `qat_state_dict`), upstream не читает: он ждёт
  ключ `modelopt`. Такие модели нужно дообучить заново через `quantize=8`. Вывод сделан по чтению кода.
- Обычные чекпойнты и конфиги переносятся без изменений.
- В шапке `yolo26-uav.yaml` осталось предупреждение не называть файл `yolo26s-p2.yaml`. С 8.4.144 upstream ищет YAML
  сначала по данному имени, так что предупреждение устарело, но и не мешает.

## Как обновляться

1. Добавить upstream и скачать его:

    ```bash
    git remote add upstream https://github.com/ultralytics/ultralytics.git
    git fetch --all --tags
    ```

2. Для каждого коммита из таблицы «Правки» проверить, не исправил ли upstream то же самое:
   `git log v8.4.164..upstream/main -- <файлы>` и `git log -S'<ключевая строка>' v8.4.164..upstream/main`.
   Upstream чинит эти места быстро: за 26 версий он полностью закрыл 8 из 17 правок прошлого форка и ещё 2 частично.
3. Пробный перенос, без изменений в рабочей копии:

    ```bash
    for c in $(git rev-list --reverse v8.4.164..feat/drone-person-configs-8.4.164); do
      git merge-tree --write-tree --name-only --merge-base=$c^ upstream/main $c >/dev/null \
        && echo "$c clean" || echo "$c CONFLICT"
    done
    ```

4. Новую ветку строить от тега upstream, а не ребейзить старую:
   `git switch -c feat/drone-person-configs-<версия> v<версия>`, затем `git cherry-pick -x` нужных коммитов. Конфликты
   разбирать в пользу upstream.
5. Обновить разделы «База» и «Правки» в этом файле.

## Как проверять

```bash
uv pip install -e ".[dev,export-base,solutions]"
ruff format --check . && ruff check .
pytest -n auto --dist=loadfile tests/ --export-env base
yolo predict model=yolo26n.pt
```

Точечно по нашим правкам:

- **Конфиги.** Модель строится по имени с масштабом (`YOLO("yolo26s-uav.yaml").info()`) и берёт веса `yolo26s.pt` с
  ожидаемой долей переноса: у `person` почти все тензоры, у `uav` голова c2/c3 = 32/128. Если вывод «Transferred N/M»
  резко упал, после обновления поменялись имена ключей или ширина головы.
- **Якоря.** `make_anchors` на bf16-фичах 160×160 даёт float32-точки, и все центры различны; `.half()`-инференс
  оставляет выход в fp16.
- **ReID.** Кроп приходит в `.pt`- и в ONNX-энкодер в RGB.
- **Трекер.** Кадр, где трекер ничего не вернул, даёт пустой `Results`.
- **Fitness.** Обучение, где первая валидация дала NaN, всё равно пишет `best.pt`.
- **QAT.** Цикл `train(quantize=8)` → экспорт в engine → val на реальной GPU.
